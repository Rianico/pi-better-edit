Each window is served in that turn, so its anchors work in the same edit. A window can also be `{ around_anchor, radius }` to centre on a line this session already served. An anchor outside this session's served rows is omitted with an inline `[Window warning: ...]`.
- read: for a file above about 200 lines, start with `mode: "outline"` before any body read. It serves one declaration line per symbol as a live anchor, so you can find the target without reading the whole file. When the edit targets that declaration line, edit from the anchor directly; do not read the body. Otherwise read only the window you need: for a function under 150 lines, read its span in one call via `{ offset, limit }`; for larger functions, read a 60-line window around the target. Do not read the whole file to verify.
- read: omit `mode` for a small file or when you need body lines to edit. Use `windows` to fetch only the target range. Pass `mode: "verbatim"` for plain text with no anchors when you will not edit (e.g. config, docs, README, SKILL.md).
- read: send one file per call as `{ file, windows?, mode? }`, the same way `edit` does. The single top-level `mode` applies to the file. To read several files, make parallel `read` calls.
