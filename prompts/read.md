Read a text file via `file`. By default each line returns as HASH│content with a 3-char alphanumeric hash — keep the default when you intend to edit the file, and use the HASH as the anchor in edit calls; pass `mode: "verbatim"` for plain file content with no HASH│ prefix when you will not edit the file. No line numbers. Images → visual attachments; Binary/directory → rejected; UTF-16/UTF-32 (BOM) → rejected; empty → HASH│ (edit to insert), or `[File is empty.]` with `mode: "verbatim"`; pageable with offset/limit (`offset` is 1-indexed; `limit` is a line count), or several disjoint ranges in one call with `windows: [{offset, limit}, ...]` (in the default `served` mode every listed window is served there, so anchors from all of them work in one edit); BOM stripped; non-UTF-8 shown as U+FFFD. To load skill content as plain text, use `read` with `mode: "verbatim"` (it shares the 238,328-line read ceiling). Hashes are file-scoped: a 3-char anchor is bound to the file it was served from, so copy anchors only from the file you are editing.

Interop: small reads (limit <= 100) may be expanded to the enclosing AST symbol before this tool runs — the served HASH│content rows and their anchors always reflect the expanded window actually returned, so copy anchors only from the rows you received. Every default-mode row (including all windows entries and post-edit diff rows) is served and its anchor usable in the next edit with no re-read, even when truncated to what is shown.
