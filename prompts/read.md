Read one text file in one call via `file`, with optional `windows` and top-level `mode`. To read several files, make parallel `read` calls. By default each line returns as HASH│content with a 4-char alphanumeric hash — keep the default when you intend to edit the file, and use the HASH as the anchor in edit calls; pass `mode: "verbatim"` for plain file content with no HASH│ prefix when you will not edit the file. The page header is the only chrome: `[path (N lines total)]` for a whole file, `[path (lines a-b of N total)]` naming the range actually shown, and `[path (verbatim, ...)]` in verbatim (`verbatim` is the only mode marker). A page the byte budget cut adds `; stopped at 50.0KB`. A multi-window call also heads each section with `[Lines s-e of N total]`; there is no footer — every header states the file's own `total`, never the count you asked for, and rows stay `HASH│content` with no row-level line numbers. Name ranges with `windows`: `[{ offset, limit }]` (offset is 1-indexed, limit a line count) or `[{ around_anchor: "a1b2", radius: 10 }]` to centre on a line this session served; at most 16 windows in the call. When a page stops short, continue from the next unshown line with `windows: [{ offset, limit }]`: the header's shown range tells you where the page ended. A file that cannot be read fails the call with the refusal naming the file. Empty files return `HASH│` (edit to insert), or `[File is empty.]` with `mode: "verbatim"`. Plain text only (no line numbers). PNG/JPG images are returned as image attachments for multimodal models. Binary/directory and UTF-16/UTF-32 files are rejected. A UTF-8 BOM is stripped; non-UTF-8 bytes are shown as U+FFFD. To load skill content as plain text, use `read` with `mode: "verbatim"` (the default `served` mode is capped at 200,000 lines by the served admission budget; `mode: "verbatim"` is not capped, though both are bounded by a 100MB size guard). Hashes are file-scoped: a 4-char anchor is bound to the file it was served from, so copy anchors only from the file you are editing.

Interop: small reads (limit <= 100) may be expanded to the enclosing AST symbol before this tool runs — the served HASH│content rows and their anchors always reflect the expanded window actually returned, so copy anchors only from the rows you received. Every default-mode row (including all windows entries and post-edit diff rows) is served and its anchor usable in the next edit with no re-read, even when truncated to what is shown.
