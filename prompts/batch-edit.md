Apply several edits in one atomic call. The complete payload is a root JSON array of tuples: `[[path, [remove_from, remove_to], replacement_text], ...]`. Each item is exactly the tuple `[path, [remove_from, remove_to], replacement_text]`, where path is a non-empty string or null to infer it from the anchors. The two anchors form an inclusive range; use an empty replacement_text to delete. Anchors are bare 3-char hashes from read or diff output. Items targeting the same file are applied in the order given. Every item is verified against what the model was shown before ANYTHING is written: if any item fails — stale or ambiguous anchor, changed range interior, never-served line, or a range that overlaps an earlier item — the whole batch is rejected and no file changes. The failing item's current range is served as fresh HASH│content rows so the model can retry without a read. Use batch_edit whenever you have multiple edits.
