## Context

The design record [`unified-error-and-warning-contract.md`](../spec/unified-error-and-warning-contract.md) proposed a closed, two-tier domain model for every rejection and applied-path diagnostic. The batch implemented it in five code commits: `218ad8a` (tagged `DomainError` registry), `0bc2b65` (unknown / foreign anchor split), `354d98b` (`W_*` tier, reversed anchors always heal), `9b7cd27` (batch and diagnostic gap closure), `e73b806` (spec §6 oracles). Review corrected two wordings against as-built behavior instead of absorbing them silently: the content-path tombstoned-boundary check (ADR-0020 decision 2 prescribed the fresh-read heading; as-built `0bc2b65` serves `[E_STALE_ANCHOR]` rows — decision 3 below amends that sentence) and the "always renders rows" shape claim (the missing-previous-hashes producer carries the headline only — decisions 1 and 3 record the hedge with its line trace).

## Decision

**The unified error and warning contract, as built. Seven checkable statements.**

1. **Strict two-tier surface.** Every diagnostic is either `[E_*]` (failed closed: zero bytes written, working buffer untouched, active leases untouched) or `[W_*]` (applied: written verbatim, or healed by the deterministic reversed-bounds swap). Format is `[<AUDIENCE>] [<CODE>] <neutral-statement>` in both tiers. `[USER] [E_REVERSED_ANCHORS]` is retired; a healed reversal narrates `[USER] [W_REVERSED_ANCHORS]` only. Reading (not re-litigable): anchors carry no order, so reversal is a property of the resolved lines of the `anchor_from`/`anchor_to` slot pair — never of the anchor strings (`src/hashline/lease-resolve.ts:198-210`). Check: `test/arch/domain-error-registry.test.ts` (`no raw [MODEL]/[USER] [E_/W_] header literal exists outside src/domain-errors.ts`).
2. **Tagged registry as the single header formatter, with totality.** `src/domain-errors.ts` owns every header through `ERROR_REGISTRY`, `WARNING_REGISTRY` and `formatWarning`; no raw `[W_*]` literal exists outside it and no `[E_*]`/`[W_*]` header literal exists outside it. Totality holds in both directions: every union member has at least one `new DomainError(code, …)` / `formatWarning(code, …)` producer in `src/`, and every produced code is a union member (`test/arch/domain-error-registry.test.ts`, AST oracle). The three ad-hoc error classes are retired: `AnchorMismatchError` and `ServedRejectionError` have zero producers in `src/`; `ServedHashEchoError` survives only as `export { DomainError as ServedHashEchoError }` (`src/hashline/served-guard.ts:126`), an import-compat alias that formats no header of its own.
3. **Anchor family with deterministic precedence and fixed readings.** The lease seam refuses in one order: a lease held for another file reports `[E_FOREIGN_ANCHOR]` before the no-lease-anywhere case reports `[E_UNKNOWN_ANCHOR]` (`src/hashline/lease-resolve.ts:100-118`). Readings: `E_FOREIGN_ANCHOR` = the anchor is leased for a file other than the one the edit names; `E_UNKNOWN_ANCHOR` = this session holds no lease for the anchor in any file; `E_STALE_ANCHOR` narrowed to "row here, identity dead" = a served anchor whose line identity no longer resolves, served with rows for a retry (`src/hashline/served-verification.ts:232-256`, including the tombstoned boundary via `throwStaleForTombstone`, `:749-765`, `cause: "tombstone"`). Hedge: the missing-previous-hashes producer (`src/mutation-engine/pipeline.ts:368-373`, `cause: "never-served"`) carries the headline only — no window exists to serve. This amends ADR-0020 decision 2's tombstoned-boundary sentence (fresh-read heading, no retry hint), which the as-built `0bc2b65` deliberately replaced with rows plus the retry hint (`test/core/served-verification.test.ts:346-380` pins it).
4. **Remedy-eligibility principle.** Payload text reports facts; a remedy clause may appear only when it is helpful, unharmful and fail-closed AND the evidence pins a single cause. When the intent is ambiguous the payload states the fact and carries no remedy, because an intent-guessing suggestion steers the model's next action (`src/domain-errors.ts:18-24`). Remedy-free by rule (no `remedy` field on the registry entry): `E_UNKNOWN` — no cause is knowable at all; `E_UNKNOWN_ANCHOR` — wrong path, wrong anchors and wrong session are indistinguishable; `E_FOREIGN_ANCHOR` — the sibling path is the actionable fact and presumes nothing; `E_UNVERIFIED_RANGE` — the served rows are the information and the model decides from them, so no retry mandate; `E_NOOP_LOOP` — the refusal's evidence pins the fact (the range already contains this text) but not the model's intent, so a remedy clause would dress a status fact as an action. (Amends the as-accepted four-entry enumeration: the as-built `d96c17e` removed the `E_NOOP_LOOP` `remedy` field and moved the fact into its `format`, so the code joined the remedy-free set by rule.) Check: those five `ERROR_REGISTRY` entries carry no `remedy`.
5. **`E_NOOP_LOOP` / `W_NOOP` split.** A no-op'd call changed nothing, so it is not a failure: the first no-op proceeds, the second identical no-op warns `[USER] [W_NOOP]`, and only the repeated resend refuses as `[E_NOOP_LOOP]` (`src/noop-guard.ts:59-99`, `NOOP_LOOP_THRESHOLD = 3` in `src/constants.ts:20`). `E_NOOP_LOOP` is remedy-free by rule: the refusal's evidence pins the fact (the range already contains this text) but not the model's intent, so a remedy clause would dress a status fact as an action.
6. **Evidence-gated disclosure of `mode: "literal"`.** The flag is exposed only through the `[E_SUSPICIOUS_TEXT]` refusal payload, so its exact double-quoted spelling is part of the contract (`suspiciousFormat` / `suspiciousTail` in `src/domain-errors.ts:217-237`). No prose surface teaches it: `prompts/` carry zero `literal` mentions. The tool schema declares the enum value without remedy prose (`src/payload-contract.ts:64-67`). Evidence-gated: the refusal fires only when `replace_with` reproduces a row actually served for this session, path and line — never for shape alone.
7. **Supersessions — the design spec is not current where it differs.** The spec's §4.2 `E_UNVERIFIED_RANGE` format text (`target anchor … has not been verified in the active session lease`) is superseded by the as-built general headline (`UNVERIFIED_HEADLINE`, `src/domain-errors.ts:196-200`); the spec's single-quoted flag spelling (`mode: 'literal'`, §4.1–§4.2) is superseded by the double-quoted `mode: "literal"`; the spec's §6 source-scan oracle sketch is superseded by the structural AST oracle (`test/arch/domain-error-registry.test.ts`: `producers()` / `warningProducers()` in both directions plus `rawHeaderLiterals()`). Do not read the spec as the contract on these three points.
