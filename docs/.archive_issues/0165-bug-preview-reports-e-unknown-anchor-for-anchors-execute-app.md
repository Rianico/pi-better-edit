## Summary

2.2.0 — after `read` serves a file's anchors, `preview`/`compPreview` reports `[E_UNKNOWN_ANCHOR]` for those anchors (`has not served the anchor`), while `execute()` on the same request applies cleanly.

## Environment

- Version: pi-better-edit 2.2.0 (also master@00f8c34), pi 0.87.0, Node 26.7.0
- Module: src/edit-tool.ts (preview path) → src/mutation-engine/pipeline.ts → src/hashline/lease-resolve.ts
- Command: `compPreview(request, cwd)` — the TUI call preview (DebouncedPreview) shows the same error

## Steps to Reproduce

1. Minimal input, pasted verbatim — `sample.ts`:

```
aaa
bbb
ccc
```

anchors from `_lineHashesPure("aaa\nbbb\nccc\n")`; call the middle one `h1`.

2. Payloads, pasted verbatim:
   - read: `{"path":"sample.ts"}`
   - edit: `{"path":"sample.ts","edits":[["h1","h1","BBB"]]}`

3. Run — one process, and the tool context must have a real `sessionManager` (this matters):

```ts
await readTool.execute("r1", { path: "sample.ts" }, undefined, undefined, ctx);   // serves anchors
const preview = await compPreview({ path: "sample.ts", edits: [["h1", "h1", "BBB"]] }, cwd);
await editTool.execute("e1", { path: "sample.ts", edits: [["h1", "h1", "BBB"]] }, undefined, undefined, ctx);
```

## Expected behavior

`preview` returns `{ diff: … }` — it previews the very request that `execute()` on the next line applies cleanly.

## Actual behavior

```
{ error: "[MODEL] [E_UNKNOWN_ANCHOR] sample.ts has not served the anchor \"h1\"; nothing was written." }
```

In the TUI, the call preview shows this error instead of the diff; the approved edit then applies fine.

## Impact & Trigger Conditions

Fires on every edit preview whose rows were served under a real `sessionManager` — i.e. all previews in the TUI, every time. It blocks the pre-approval preview completely (no diff is ever shown); execution is unaffected. The test suite never fires it: `setupIntegrationTest` serves through `{ cwd, ui: { notify() {} } } as any` (test/support/fixtures.ts) — no `sessionManager` — so the read's leases and the preview's lookups land on the same fallback key and agree.

## Root Cause / Suggested Fixes (optional)

Hypothesis — the preview resolves anchors through the lease lookup with a session key that was never served anything:

1. `EditTool.preview` calls `enginePreview(normalized, cwd, { accessMode: R_OK })` — no `sessionKey` (src/edit-tool.ts). It has none to pass: `preview(request, cwd)` runs from `DebouncedPreview` at render time.
2. `runMutations` fills it in with `options?.sessionKey ?? sessionKeyFor(undefined)` (src/mutation-engine/pipeline.ts:800).
3. `sessionKeyFor` without a session returns `fallbackSessionKey ??= randomUUID()` (src/served-session/session.ts:32).
4. `resolveEdit` takes its lease-first branch (`served && identity`, src/hashline/apply.ts:191); `resolveLeasedEdit` finds no lease for the anchor and throws (src/hashline/lease-resolve.ts:118).

`execute()` passes `sessionKeyFor(ctx)` — the key the rows were served under — which is why the same request applies there.

Alternatives, with tradeoffs:

- **Route preview to content resolution** — pass `served`/`sessionKey` as undefined from the preview path, so `resolveEdit` takes its *"no mirror, no lease source"* branch (`resolveEditByContent`, anchor algebra). Tradeoff: preview loses lease-based verification and the rebase/fresh-read display (a drifted anchor previews as absent instead of rejecting with a fresh read). Preview is display-only; `execute()` keeps verification. I've tested this fix locally.
- **Thread the session into preview** (`preview(request, cwd, sessionKey?)`, captured on the TUI side). Tradeoff: verification semantics stay identical, but the render path — which today carries no session — grows a new input, and external callers must supply one.
- **Make `sessionKeyFor` fail without a session** instead of returning a random key. Tradeoff: honest, and the session-less caller already has semantics (*"a session-less caller keeps no tally"*, apply.ts:326); larger blast radius — every no-session fixture and library caller updates.

The fallback in `sessionKeyFor` is worth a look regardless of the fix chosen: it returns a random key instead of failing, so any caller without a session verifies against one that was never served anything. Preview is where it surfaces first.

## Agent Brief

**Category:** bug
**Summary:** Tool preview reports E_UNKNOWN_ANCHOR for anchors that execute() applies successfully

**Current behavior:**
When tool context carries a real session (as in the TUI), reading a file serves its rows under that session key, and `execute()` applies edits to those anchors fine. But `preview()` of the identical edit fails with `E_UNKNOWN_ANCHOR` ("has not served the anchor ... nothing was written"). The existing test suite never catches this because test fixtures build tool context without a session manager, so read and preview agree on the same fallback key and the divergence stays hidden.

**Desired behavior:**
Previewing an edit against anchors served by a prior read must succeed whenever executing the same edit would succeed, regardless of whether the tool context carries a session. A missing session at a mutation entrypoint must fail loudly at the boundary rather than silently resolving against an unserved session key and producing a misleading "anchor not served" error. The misleading symptom (anchor WAS served, under a different key) must disappear for every mutation entrypoint, not just preview.

**Key interfaces:**
- `EditTool.preview()` vs `EditTool.execute()`: execute threads the tool context's session key into the mutation pipeline; preview does not, so the pipeline falls back to minting a fresh random session key that was never served anything.
- `sessionKeyFor()`: with no session it mints a random key instead of failing — this converts a programming error (missing session) into a user-facing lease error. Any fix should address this fallback, not just the one preview call site (there is more than one fallback site in the mutation pipeline).
- Lease/lineage verification must keep working: preview must not silently drop to unverified content resolution just to make the error go away.

**Acceptance criteria:**
- [ ] A regression test reads a file under tool context WITH a session manager, then previews an edit to a served anchor and gets a diff (not E_UNKNOWN_ANCHOR)
- [ ] The same test executing the edit succeeds, as before
- [ ] A mutation entrypoint invoked without any session fails loudly at the boundary instead of reporting E_UNKNOWN_ANCHOR
- [ ] Existing lease/span-verification behavior is unchanged (no silent downgrade of preview to unverified resolution)
- [ ] Full verification passes: lint, format, typecheck, test coverage per project CONTRIBUTING

**Out of scope:**
- Redesigning session-keyed served state itself
- Changing what E_UNKNOWN_ANCHOR means for genuinely unserved anchors
- Any migration of existing callers beyond what the fix requires
