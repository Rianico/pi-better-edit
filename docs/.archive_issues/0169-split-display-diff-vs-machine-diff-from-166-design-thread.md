## Context

Split from #166 (second comment). Today a single `details.diff` string serves two audiences:

- model: `finalizeResult` / `finalizeToolResult` send `details.diff` (context=1, via `buildChanged` in `src/edit-response.ts:188,301` and `pipeline.ts:1240` dense recompute) as retry-critical context;
- user: `buildAppliedText` renders the same string through `fmtResult` coloring.

The context-4 preview (`edit-tool.ts:preview`) is the only display-tailored artifact. Reporter notes the applied diff is model-legibility-first, single-line-per-change, which is fine for retry but less scannable for humans, and suggests either keeping as-is (design call) or serving a display-tailored diff alongside the machine one.

## Question for maintainer

Keep the single-string contract, or serve two diffs (display vs machine)? If two: who owns each (`finalizeResult` vs `buildAppliedText`), token cost, and does the display diff need served-row/lease semantics or is it user-facing signal only?

## Decision (grilled with maintainer)

- **Single shared projection**: human display == model display. No second pipeline. Preview, applied, and display render the same text with different context params.
- **Source of truth** = disk bytes + lease store. Coordinates resolve through leases, never from projection text. Pinned in CONTEXT.md as `source of truth` / `projection`.
- **Collapse contract**: middle-gap markers carry omitted counts, unifying with the ADR-0024 removed-lines style (` - ... [N lines omitted] ...`); bare `...` only where nothing is hidden. Collapse allowed only with dense lease coverage (the collapse invariant: a projection may hide text only while every hidden row stays lease-covered).

## Decision update (round 2, grilled with maintainer)

- **Span taxonomy** (replaces "middle-gap markers"): hidden spans come in two kinds — **untouched-span** (middle gap) and **deleted-span** (removed run). Added spans are never hidden (new lines carry new anchors the model must learn textually).
- **Rescoped collapse invariant**: untouched-hidden rows stay lease-covered; deleted-hidden spans are exactly counted (the count drives the old-side cursor — wrong count is #166-class desync); added rows always render. Giant-paste cost accepted as a known limitation.
- **Diction**: unify to qualified counts (`[N lines untouched]` / `[N lines deleted]`); bare `...` only at leading/trailing edges where nothing is hidden.
- Stated-not-built: single renderer with context params only; model path never parses projection text for coordinates. The removed-run collapse (ADR-0024 style) is the template, not the exception.

## Agent Brief

**Category:** enhancement
**Summary:** Formalize the single-projection contract: counted markers per span kind, stated collapse invariant, audit test

**Current behavior:**
`genDiff` renders one shared text for preview, applied, and display, but the contract is unstated. Middle-gap collapse emits a bare marker with no omitted count; removed-run collapse emits a counted marker; added lines always render. Nothing asserts anchor resolvability or count exactness across gap sizes and contexts.

**Desired behavior:**
- Marker diction unified per span kind: untouched-spans render `[N lines untouched]`, deleted-spans `[N lines deleted]`; bare `...` only at leading/trailing edges where nothing is hidden.
- Collapse invariant holds per span: untouched-hidden rows stay lease-covered; deleted-hidden spans are exactly counted (count drives the old-side cursor); added rows always render.
- Purity: single renderer, context param only — no caller hand-edits the string; the model path never parses projection text for coordinates.
- An audit test over a gap-size by context corpus asserts every emitted anchor resolves and every marker count matches its skipped span (must fail without the #166 guard).

**Key interfaces:**
- `genDiff()` return contract: every emitted row-s anchor equals the true new-file line-s content hash; every marker-s count equals its skipped span, lease-covered (untouched) or cursor-exact (deleted).
- Gap-collapse step: trim-vs-marker decision per span kind, counters advancing past all hidden rows.

**Acceptance criteria:**
- [ ] A 275-line middle gap renders `... [275 lines untouched] ...` with aligned anchors on both sides.
- [ ] A large deleted run renders `... [N lines deleted] ...` with exact N and aligned old-side anchors after it.
- [ ] Audit test red without the #166 guard, green with it; existing suites, lint, typecheck green.

**Out of scope:**
- Second pipeline or per-audience renderers; context-size changes; giant-paste truncation (known accepted cost); #170 (ctx-0 defect); #171 (classification refactor).

## Decision: leading-edge exception accepted

The leading-edge trim keeps its bare ` ...` marker (no omitted count) while hiding lease-covered rows. Rationale: boundary-clipping, not a span — the reader never had those rows in view, unlike a middle gap that interrupts visible content. Anchors are unaffected (cursors advance past the hidden span). The `genDiff` contract comment documents this as intended behavior. No action.
